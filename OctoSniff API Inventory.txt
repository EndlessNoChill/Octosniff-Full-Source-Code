1. RESOLVER / XRESOLVER QUICK REFERENCE
============================================================

Production software API base:
  https://backend.octosniff.net/api/software/v1

Primary resolver
  Method: POST
  URL:    https://backend.octosniff.net/api/software/v1/resolve
  Use:    Generic IP, PlayStation username, and Xbox gamertag resolver.

  Confirmed JSON request type: ResolveRequest
    ip           string or null  - resolve an IP address
    playstation  string or null  - resolve a PSN username
    xbox         string or null  - resolve an Xbox gamertag

  Send only the field for the lookup being performed. Examples:
    Xbox / xResolver body:        {"xbox":"ExampleGamertag"}
    PlayStation resolver body:    {"playstation":"ExamplePSNName"}
    IP resolver body:             {"ip":"203.0.113.10"}

  Confirmed ResolverResource response fields:
    asn, city, country, country_code, ddos, district, hostname, ip, isp,
    latitude, longitude, organization, state, usernames, zip_code

  Each item in usernames can contain:
    console_id, ip_address, type, username

  Important integration finding:
    OctoSniff 5.1.1 does NOT contain a separate fixed /xresolver route.
    Xbox lookups use POST /resolve with the JSON field "xbox". PSN lookups
    use the same route with "playstation".

Resolver usage/count
  Method: GET
  URL:    https://backend.octosniff.net/api/software/v1/resolve/count
  Use:    Returns resolver counts/availability for PlayStation and Xbox.
  Confirmed response fields: playstation, xbox

Legacy packet-assisted PlayStation resolver
  Method: POST
  URL:    https://backend.octosniff.net/api/software/v1/decrypt/playstation
  Use:    Legacy PlayStation packet/decryption lookup flow.
  Confirmed JSON fields: client, data, target

Submit a resolver association/token
  Method: POST
  URL:    https://backend.octosniff.net/api/software/v1/submit
  Use:    Stores/completes a resolver association from the packet flow.
  Confirmed JSON fields: ip, submit_token

Submit a Party username/IP association
  Method: POST
  URL:    https://backend.octosniff.net/api/software/v1/party/submit
  Confirmed JSON fields: ip, username

Internal application call paths recovered from the client:
  PSN:
    App.ResolvePlaystationUsername
      -> requireSubEntitlement
      -> ipresolver.ResolvePlaystationUsername
      -> Client.ResolveIP(context, "", psnUsername, "")
      -> POST /resolve using "playstation"

  Xbox / xResolver:
    App.ResolveXboxGamertag
      -> requireSubEntitlement
      -> ipresolver.ResolveXboxGamertag
      -> Client.ResolveIP(context, "", "", xboxGamertag)
      -> POST /resolve using "xbox"

  Both application lookups trim the entered name and use a 10-second timeout.

8. RECOVERY AND CONFIDENCE NOTES
============================================================

  - The generated /v1 route table, methods, resolver request fields, and
    response fields were recovered directly from the exact 5.1.1 executable.
  - The packed program was unpacked only in a temporary, isolated application
    data profile while outbound traffic was blocked. No live API calls were
    made for this recovery.
  - Existing assessment PDFs and source notes were used to corroborate the
    resolver call chains and Party behavior.
  - Browser-generated WebView component URLs were excluded unless OctoSniff's
    own code or observed Sony sign-in flow used them.
  - Dynamic URLs returned by the backend (for example update downloads or an
    Xbox authorization URL) cannot be listed as fixed routes; the API route
    that returns them is included above.
  - API access still requires the application's authorized authentication,
    entitlement, device proof, TLS pinning/mTLS, or gateway credentials where
    applicable.
